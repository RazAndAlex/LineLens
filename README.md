# LineLens

Local-first diagnostics for industrial machine data. Upload a CSV exported from
a PLC, historian, SCADA system, dashboard, or production database; LineLens
validates it, calculates trustworthy totals, and shows what it found.

> **Python calculates the truth.**

Industrial dashboards routinely **sum cumulative totalizers** — odometers that
should be differenced — and quietly report idle time or parts counts that are
3.6× too high. LineLens finds that class of mistake. Every calculation,
validation, and anomaly detection is deterministic — no AI, no guessed totals,
no invented severities, nothing touches a raw row.

## What it does

- Accept one CSV; preview and profile it.
- Let the user map columns (with heuristic suggestions) and designate counters.
- Validate timestamps, durations, and machine states; surface affected rows.
- Classify counters (cumulative / unknown) and detect resets with a cause.
- Calculate state, production, and downtime totals (overall / day / shift).
- Read the period as a command deck: a sticky hero OEE with A·P·Q satellites,
  then **Diagnosis** (findings + the naive-vs-honest contrast), **Now** (state/
  production/downtime charts, the only section the date range scopes), **Loss**
  (the bottles-lost Pareto), **Future** (a banded forecast of daily good output
  with what-if levers that lift the horizon), and **Health** (Performance
  degradation, MTBF band, and the maintenance due window in one view). Every
  future quantity ships as a band, never a single confident number.
- Flag the headline aggregation problem: a cumulative totalizer a dashboard
  **sums** instead of differences (naive sum vs honest total).
- Export a cleaned CSV and a structured findings file (JSON/CSV).

## Stack

Python and pandas (core). The UI is FastAPI (`server/`, `web` extra) serving a
React + TypeScript frontend (`web/`, Vite + Tailwind + ECharts) built to
`web/dist`; Node.js is only needed to rebuild the frontend. scikit-learn stays
in its own `forecast` extra. Dataclasses for models; Pydantic only if a
boundary earns it. Full dependency rationale in `docs/plan.md` §F.

## Setup

Requires Python ≥ 3.12 and [uv](https://docs.astral.sh/uv/).

```bash
uv sync                              # core library + test deps
uv sync --extra web --extra forecast # the app (API + learned forecast)
```

## Run the app

```bash
uv run python api.py    # or double-click LineLens.bat
```

A browser opens at http://127.0.0.1:8741. The frontend ships prebuilt in
`web/dist`; if it's missing, `LineLens.bat` builds it with npm first (the one
moment Node.js is required). If port 8741 is busy, uvicorn exits with a bind
error — close whatever owns it (usually an older LineLens window) and start
again.

Upload one of the synthetic datasets and map its columns:

- `sample_data/valid_event.csv` — clean event data: state / production / downtime
  totals, no findings.
- `sample_data/golden/cumulative_with_reset.csv` — a cumulative parts totalizer
  with one reset; map `parts_total` as a counter to see the reset finding and the
  naive-sum-vs-honest-total contrast (235 vs 75).
- `sample_data/golden/totalizer_summed.csv` — the §5 scenario: a cumulative
  idle-time totalizer a dashboard sums (87,000 naive vs 24,000 honest).

## Tests

```bash
uv run pytest
```

Unit, integration, golden-driven, and API end-to-end tests; the core suite
needs no UI deps. Golden datasets under `sample_data/golden/` carry
hand-truthed `.expected.json` and are the source of truth for numbers — never
AI-derived.

## Project layout

```
linelens/        # the library: ingestion → schema → validation → counters → summaries → reporting
server/          # FastAPI backend: routes, serializers, pure UI-free logic (ADR-0011)
web/             # React + TypeScript frontend (Vite + Tailwind + ECharts); web/dist is served
api.py           # entry point: serves the API + the built frontend on 127.0.0.1:8741
archive/         # frozen history (streamlit-ui/ = the old Streamlit UI, reference only)
tests/           # unit + integration + golden-driven + API tests
sample_data/     # synthetic fixtures; golden/ holds hand-truthed sets
examples/        # committed, regenerable reports (M8) — read on GitHub without running
scripts/         # render_examples.py — regenerates examples/
docs/            # plan + milestone designs
```

See `docs/plan.md` §B for the target structure and dependency direction.
