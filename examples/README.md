# Example reports

Committed, ready-to-read reports generated by LineLens against the synthetic
datasets in [`../sample_data/`](../sample_data). Open one to see exactly what the
tool produces — no install, no run.

| Example | Dataset | What it shows |
|---|---|---|
| [`totalizer_summed.findings.md`](totalizer_summed.findings.md) | `golden/totalizer_summed.csv` | **The headline (brief §5).** A cumulative idle-time totalizer a dashboard *sums*: **87,000 naive vs 24,000 honest** — the contrast *is* the diagnosis. |
| [`cumulative_with_reset.findings.md`](cumulative_with_reset.findings.md) | `golden/cumulative_with_reset.csv` | A cumulative parts totalizer with one reset: a `PROBABLE_COUNTER_RESET` finding (row 6) **plus** the **235 naive vs 75 honest** contrast. |
| [`valid_event.findings.md`](valid_event.findings.md) | `valid_event.csv` | The clean case — state / production / downtime totals, **"No problems detected."** |

Each `.findings.md` is the deterministic human-readable report; the matching
`.findings.json` is the versioned findings blob (`schema_version: "1.0"`) the
optional AI layer (M7) reads to add "likely cause" prose. Both are produced by
`linelens.reporting` — never hand-edited.

## Regenerate

```bash
uv run python scripts/render_examples.py
```

A drift-guard test (`tests/test_examples.py`) re-renders and asserts these
committed files match the library's current output, so a code change that alters
rendering is caught before it ships a stale example.
